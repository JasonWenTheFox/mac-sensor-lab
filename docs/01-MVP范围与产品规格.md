# 01 MVP 范围与产品规格

## MVP 成功定义

在当前 Apple Silicon Mac 上，用户能够打开原生 App，立即看到导航和传感器状态；数秒内得到至少一组真实、无需提权的系统/电源读数；能够区分可用、加载中、无权限、不支持和实验性状态；能够导出不含唯一标识的快照。

## 信息架构

### Overview

以卡片展示：

- System
- Power & Battery
- Thermals
- Display
- Storage
- Disk Activity
- Experimental Hardware

每张卡只显示关键指标和状态，不堆满跳动数字。

### Raw Sensors

按 Provider 分组展示：

- 通道名称和稳定 ID；
- 当前值与单位；
- 原始/派生/估算/校准标记；
- 数据来源和最后更新时间；
- 可用性、权限和错误详情。

### Experiments

首版显示可规划实验及其依赖状态。只有底层 Provider 可用且经过验证后才启用真正测量。环境光允许在保留原始通道的前提下，用用户提供的外部 lux 参考生成单点估算，并可由用户主动导入/导出可移植的单点校准 JSON；上盖角度允许设置本地参考并显示相对变化。

低速加速度历史可以展示 RMS 变化量和峰峰值，但 1–10 秒 Dashboard 采样不得命名或解释为振动频率、频谱或高频记录。

### About & Diagnostics

显示版本、构建信息、隐私说明、上游致谢、Provider 诊断和导出入口；不显示机器唯一标识。

## 交互要求

- 首屏不等待硬件枚举；
- Provider 独立异步加载；
- 可手动 Refresh；
- 自动采样可选择 1、2、5 或 10 秒，并可暂停/恢复和清空内存历史；
- 采样间隔应持久化，暂停状态不应持久化；Settings 与工具栏共享同一选项；
- 连续记录必须由用户主动选择目标文件，区分原始值与格式化值并具有硬性文件上限；
- 失败状态给出原因和安全下一步，不提供 `sudo App` 之类快捷方式；
- Diagnostics 必须分别统计权限不足、不可用和错误，不得把不同原因合并成同一个“Unavailable”数字；
- 图表窗口只保留当前绘图/派生功能需要的通道，总计最多 256 条序列、每条 600 个严格递增时间戳的内存样本；
- UI 首版使用英文，代码和数据 ID 使用稳定英文；中文文档先完整保留。
- Raw Sensors 搜索只过滤当前显示；不得改写原始 Snapshot、采样历史或导出数据。
- 光照校准导入必须先完成结构和值域验证，失败时不得替换现有校准；校准文件不得包含设备标识。
- 诊断支持报告只导出 Provider 状态和稳定通道元数据，不得导出传感器读数、摘要、备注、来源字符串或路径。
- 采样健康诊断只保留刷新次数/耗时、Provider 状态切换和连续异常计数，不保留读数、Snapshot 时间戳或自由文本。
- 截图和无硬件演示必须使用显式 Demo 模式；全界面持续标识 fixture 数据，并与真实采样/校准偏好隔离。

## MVP 验收指标

- `swift build` 和 `swift test` 成功；
- CLI 自检输出合法 JSON；
- `.app` 能从 Finder/open 启动并显示窗口；
- 首次渲染不依赖慢速 Provider；
- 无权限或无设备时不崩溃；
- 导出不包含序列号、UDID、Hardware UUID、用户名或主机名；
- 所有显示值有单位、来源和数据性质；
- 第三方代码和参考项目许可证可追溯。
