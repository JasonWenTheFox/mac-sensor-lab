# 07 硬件清单与能力语义

更新：2026-09-11（v0.3.1 + E2b/E3/E2c/E2d/E2e/E2f/E4/E5a/E5b/E7a/E7b/E7c/E7d/E8a/E8b/E9a/E9b）

## 为什么要拆分能力语义

一个 Mac 上“有这块硬件”不等于“App 有可用读取路径”，更不等于“已经有可以向用户解释的功能”。v0.3.0 保留旧的 `SensorCapability`，但不再用它承载所有语义。

每个 Provider/Snapshot 现在同时包含：

- `category`：界面导航分类；
- `domain`：实际硬件领域，例如 CPU、GPU、Memory、Lid；
- `accessLevel`：读取路径的权限与公开程度；
- `compatibilityConfidence`：当前兼容性结论所依赖的证据级别；
- `readiness`：从硬件存在到用户功能的五个独立检查点；
- `kind`：每个通道的 Raw/Derived/Estimated/Calibrated 数据性质。

## 访问级别

| `SensorAccessLevel` | 含义 |
|---|---|
| `publicOrdinary` | 公开 API，普通用户进程可读 |
| `publicTCC` | 公开 API，需要麦克风/定位等 TCC 隐私授权 |
| `publicEntitlement` | 公开 API，但需要 entitlement 或特定签名能力 |
| `undocumentedOrdinary` | 字段或语义未文档化，但当前普通进程可读 |
| `privilegedHelper` | 只能由最小特权 Helper 读取；主 App 不得以 root 运行 |
| `privateExperimental` | 私有/逆向接口，仅作实验性读取 |
| `platformBlocked` | 当前平台没有合理、可发行的路径 |
| `hardwareAbsent` | 已知当前硬件不存在 |

`SensorCapability` 仅作向后兼容的粗粒度字段。新代码和新导出应优先使用 `accessLevel`。

## 五段就绪状态

| 字段 | 回答的问题 |
|---|---|
| `hardwarePresence` | 硬件/服务是否存在，或一组能力是否为 mixed |
| `decoder` | 未文档化报告或字段是否有已验证的解码器 |
| `readPath` | 当前读取是否 ready、limited、permissionRequired、unavailable 或 failed |
| `stream` | 应连续产生数据的 Provider 是否正在产生数据 |
| `feature` | 最终用户功能是 ready、partial、blocked 还是 unsupported |

这些字段不会把“未检测到”自动解释为“硬件一定不存在”。只有明确的发现 Provider 会输出 `absent`/`mixed`；其他失败路径保留 `unknown`。SPU 发现和实验硬件发现即使读取成功，`feature` 也只是 `partial`，不会单凭存在性解锁称重等测量。

## 硬件清单隐私边界

v0.3.0 新增的六个 Provider 只读取：

- `hw.model` 的长度受限、非唯一机型类别；
- 经固定格式验证的 Apple M 系列名称；
- 物理/逻辑核心数，以及自洽时的性能核/能效核数；
- 物理内存容量与 Metal 统一内存布局；
- Metal 公开的 GPU 名称、工作集/缓冲区限制、线程组限制和能力布尔值；
- LocalAuthentication 报告的 Touch ID 能力类型。

不读取序列号、Hardware UUID、UDID、主机名、用户名、Metal `registryID`、生物识别录入状态或认证结果。Touch ID 检查不弹出认证框，也不由 Touch ID 反推 Secure Enclave。

v0.3.1 新增两个公开 API Provider：

- `hardware.display` 使用 CoreGraphics/AppKit 读取本次会话中的显示器顺序、当前 pixels/points、模式数、最高报告像素模式、帧率/可变刷新、粗粒度色彩模型、Display P3、EDR 与物理尺寸。会话序号不是持久标识；不读取/导出显示 ID、名称、EDID、ICC 配置名或序列号。CoreGraphics 在 EDID 缺失时可能按 72 DPI 估算物理尺寸，因此尺寸、对角线和 PPI 均标为 Estimated。
- `hardware.storage` 使用 Disk Arbitration 只汇总系统卷关联整盘的协议白名单类别、internal/removable/ejectable/writable、介质容量、块大小和分区方案类别。设备型号/厂商/修订、序列号、GUID/UUID、BSD 名、registry 路径、卷名和挂载路径均被排除；SMART/NVMe 健康不从 Disk Arbitration 元数据推断。

E2b 已完成两项实现前设计，E2e/E2f 已落地其中的显示校准 core 与最小界面：

- Display calibration session 只在当前 App 会话内用内部 `CGDirectDisplayID` 绑定显示对象和 mode signature；公开 state 不含该 ID，且不持久、哈希或导出任何 display ID/EDID/serial。E2e 已实现水平几何换算、generation/revision 过期保护和 topology/mode 精确失效；E2f 在 Experiments 中加入跟随窗口当前屏幕的水平尺，将同一 context 下的 System Estimated 与 User Calibrated 结果并列。仍未增加 Provider/Channel 或 Snapshot/导出字段，Demo 也不读取真实屏幕。
- Apple 公开 IOKit `IONVMeSMARTInterface` 的普通用户只读路径已在一台测试 Mac 上用无标识符探针证实；字段语义、UInt128 计数、身份排除和失败状态见 [`08-显示校准与NVMe健康可行性.md`](08-显示校准与NVMe健康可行性.md)。E2c/E2d 已据此加入 `storage.nvme_health` 标量和十组无损累计计数，仍保留 `singleModelObserved`，不能代替跨机型验证。

E2c/E2d 的 `storage.nvme_health` 只读取当前系统卷整盘的 `SMARTReadData`，输出 `critical_warning_bits`、五个已知 warning 布尔值、`unknown_warning_present`、`composite_temperature`、`available_spare`、`available_spare_threshold`、`percentage_used`、十组 128-bit Raw 累计计数和两个 Data Units Derived 计数字节值。Raw 计数的 `value` 为 `nil`，无损十进制值放在 `formattedValue`；Derived 通道是报告单位的精确×512,000，但由于 Data Units 向上取整，不声称为精确历史 I/O 字节数。Provider 至少缓存 60 秒；温度由 Kelvin 派生为摄氏度，percentage used 明确为可超过 100% 的控制器寿命消耗估算。Provider 不读取 identify、设备名、serial、BSD/registry 路径或详细错误日志，不做 self-test、写操作或单一健康评分。

E3 对 IOReport 得到不同的分类：三个精确白名单组在一台 Apple Silicon Mac 上可以普通权限订阅和采样，但 App 侧消费 API 没有公开 header/文档，因此候选 Access 是 `privateExperimental`，不是 `publicOrdinary`。当前只加入无私有符号的纯 metadata/delta policy，Standard App 没有注册 Provider 或链接 `libIOReport`；详见 [`09-IOReport普通权限可行性.md`](09-IOReport普通权限可行性.md)。

E4 已加入公开 AppKit 的 Force Touch Pressure Lab。它不是 Provider，也不进入 Snapshot/导出：用户开始后仅由交互区自己的 `NSView` 接收 pressure 事件，显示 stage-local 0…1 值、stage、stageTransition、分段曲线和 stage 2 进入次数。历史只在内存中保留最多 240 点，停止后不再采集、离页清空；无输入 monitor、raw contacts 或设备 ID。IOKit Force Touch presence 仅是提示，当前鼠标事件是否声明 pressure 才是本次输入的运行时证据。

E5a 新增 `connectivity.wifi_radio`。它只读取公开 CoreWLAN 无线电 getter，输出固定开关/服务/关联状态、RSSI/noise、派生 SNR、频道/宽度/频段、PHY、安全模式、协商发送速率和发送功率；错误哨兵或未知枚举省略，接口未报告不会被解释为硬件一定不存在。SSID/BSSID、MAC/IP、接口名、国家代码、位置和扫描结果均未读取，当前版本也没有 Location 请求或 Wi-Fi identity entitlement。字段矩阵与后续 E5b 门槛见 [`10-Wi-Fi无线电边界.md`](10-Wi-Fi无线电边界.md)。

E5b 没有增加 Provider 或导出 schema，而是在 Experiments 加入独立、用户二次确认的 Nearby Wi-Fi Channels。它只在按钮触发后执行一次公开 CoreWLAN scan，把最多 512 条瞬时结果立即归约为 band/channel/record count/RSSI/channel width，然后丢弃 `CWNetwork` 对象；不访问 SSID/SSIDData/BSSID/country code/information elements、接口身份或 scan cache。结果仅存在当前面板，离页清除；20 秒 UI watchdog 和停止等待会拒绝迟到结果，原同步调用结束前禁止新扫描，结束后冷却 10 秒。当前仍无 Location usage description、Core Location 代码和 Wi-Fi identity entitlement。

E7a 新增 `hardware.audio`。它通过公开 Core Audio HAL 属性发布有界设备/输入/输出/双工数量，以及当前默认输入/输出的固定 transport、通道数、标称采样率和 device latency。AudioDevice 句柄只在一次读取内临时使用；不读取 UID/model UID、名称、厂商或驱动自由文本。Provider 不创建或启动音频 IO、不采集 PCM、不录音，也不请求麦克风 TCC；合法的 0-buffer 单向设备配置不会被误判为损坏。字段、身份和未来录音权限门槛见 [`11-Audio硬件清单边界.md`](11-Audio硬件清单边界.md)。

E7b…E7d 不增加 Provider 或导出 schema，而是在 Experiments 中加入隔离的 Sound Input Check。未授权时第一次开始只展示说明，用户二次确认才可能请求麦克风 TCC；授权后用 `AVAudioEngine` 接收 Float32 PCM。每个 buffer 的原始样本只在回调内被即时归约为最多 128 个通道平均波形分箱、全通道 RMS/峰值和以 1.0 为满刻度的 dBFS；面板最多保留 300 个电平历史点。相对频谱对 256…2,048 帧去均值 Hann 窗口使用可复用 Accelerate DFT setup，最快 10 Hz 更新，保留最多 128 个正频率带和一个有限分辨率的最强非 DC 分箱中心。会话最长五分钟，停止、离页、格式/设备配置改变、休眠或 App 终止都释放。原始样本不录制、持久或导出；派生值只存在面板内存，离页清空，不进入 Snapshot/Diagnostics。

E8b 已实现 USB Device Tree。公开 IOKit source 以普通权限枚举当前 `IOUSBHostDevice` / `IOUSBHostInterface`，逐字段读取固定 typed numeric key：VID/PID、`bcdDevice`、device/interface class triple、current configuration、connection speed、interface number 与 alternate setting。动态 USB 树不进入 Provider：用户在 Hardware Inventory 主动读取一次后，纯值 reducer 只构造 session ordinal 和当次父子关系，离页清空，不自动采样或进入 Snapshot/Diagnostics/导出。计数、字段、拓扑和生命周期由 fixture 与源码审计覆盖；真实 source 另通过不打印值的普通权限 smoke。USB specification version 与 power 没有满足当前边界的公开只读字段；serial/container/ECID/UDID/signature、location/path/entry ID/address、自由文本和任何 device open/request/configure/reset 均排除。详见 [`12-USB设备清单边界.md`](12-USB设备清单边界.md)。

E9b 已实现 Camera Capabilities。公开 AVFoundation source 只用固定 `.builtInWideAngleCamera` / `.external` + `.video` + `.unspecified` discovery，并把 type/position/transport、format count、encoded dimensions、fps range、autofocus 和 color space 送入有界纯值 reducer。结果只有 session ordinal，用户点击后读取一次，约两秒后停止等待并丢弃迟到呈现，底层返回前保持单飞，离页清空，不进入 Provider/Snapshot/Diagnostics/导出。Info.plist 的 Continuity 独立分类键与 transport 过滤共同排除 Continuity Camera，Desk View 也不在 allowlist；没有 Camera purpose string/entitlement/authorization/input/session/output/frame。详见 [`13-Camera硬件清单边界.md`](13-Camera硬件清单边界.md)。

## 导出 schema

- 完整 JSON Snapshot：顶层为 `{ "schemaVersion": 1, "snapshots": [...] }`；包含真实读数，仅用于用户主动的本地导出，不应直接上传公开 Issue。v0.2 及更早版是无 schema 的顶层数组。
- Privacy-Safe Diagnostics：`schemaVersion: 3`；保留 Provider/Channel 稳定 ID、状态、语义字段和无值健康计数，省略读数、格式化值、摘要、备注、来源和 Snapshot 时间。
- CSV Snapshot/连续记录：表头保留旧 `capability` 并新增 domain/access/evidence 和五段 readiness 列；它包含真实读数，不是隐私安全诊断。

新老 Provider/Channel 稳定 ID 保持不变。Demo 与 live registry 使用相同 Provider 顺序、名称、分类和能力语义；Demo 仍然使用明确标记的合成值。

## 仍未实现

- 最小特权 Helper 及其认证/XPC/安装/卸载设计；
- NVMe SMART 跨机型验证；
- IOReport Experimental adapter、CPU residency、CPU/GPU/ANE/DRAM energy，以及频率/Media Engine/bandwidth 的跨机语义验证；
- 显示器全屏纯色、灰阶、渐变、坏点和动态刷新测试；物理尺的垂直轴、对角线与跨会话校准仍未实现；
- 私有 Force Touch raw contacts、面积、逐触点压力和称重校准；
- Wi-Fi 网络身份、真实空口占用/干扰测量和漫游观察；附近频道的非身份瞬时记录摘要已实现，但不等同拥塞分析；
- microphone 声源/音高/语音/环境识别、dBA/dB SPL/校准响度或定位 Provider；Sound Input Check 已实现用户主动的 TCC/PCM 生命周期与有界 waveform/RMS/peak/dBFS/相对频谱，但不保留原始样本；
- USB version/power、跨刷新稳定设备身份与 Thunderbolt/USB4 拓扑；E8b 的 session-only USB Device Tree 已实现，但这些字段仍不具备满足当前边界的公开只读路径；
- Neural Engine 实时利用率、GNSS、气压计、磁力计等当前没有可审计路径的数据。

上述功能不会因为存在性检测而被标记为已完成。
