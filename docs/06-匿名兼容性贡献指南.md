# 06 匿名兼容性贡献指南

不同 Mac 机型和 macOS 版本可能暴露不同的 HID、SMC、AGX 和电池字段。兼容性贡献的目标是确认 Provider 的可用状态与结构，不是收集其他人的真实读数或设备身份。

## 推荐流程

1. 使用与 Issue 对应的 commit 构建或运行 App；
2. 在 Diagnostics 中确认各 Provider 的状态；
3. 如需附件，只使用 `Export Privacy-Safe Diagnostics…` 生成的 JSON；
4. 提交前在文本编辑器中自行查看该文件；它应只包含 schema、App 版本、生成时间、稳定 ID、类别、状态、能力等级、单位和数据性质；
5. 使用 GitHub 的 `Privacy-safe compatibility report` 表单，填写宽泛产品家族、CPU 架构、macOS 主/次版本、Provider 状态和复现步骤；
6. 维护者先把结构差异转成最小匿名 fixture，再修改解析器或白名单并运行完整测试。

诊断导出会在运行时拒绝非法、重复或机器识别性 Provider/通道 ID，但提交者仍需在上传前人工检查附件。程序不会自动上传任何文件。

## 不要提交

- JSON/CSV 完整 Snapshot 或连续记录；
- `ioreg`、`system_profiler`、`sysdiagnose` 或完整崩溃转储；
- 序列号、Hardware UUID、UDID、用户名、主机名、账户、IP、MAC、SSID 或 BSSID；
- 用户目录、挂载点、文件路径或第三方应用列表；
- 含真实传感器数值的截图、视频或长时间采样；
- 麦克风录音、位置或其他受保护数据。

如果定位问题确实需要以上材料，不要放入公开 Issue。安全问题使用仓库 Security 页的 **Report a vulnerability** 私密入口；普通兼容性问题仍应先缩减为无读数、无标识的最小证据。私密入口不可用时应暂缓提交，而不是降低隐私标准。

## 可接受的最小证据

- `Architecture: Apple Silicon`；
- `Broad Mac family: MacBook Pro`；
- `macOS: 15.6`；
- `motion.spu_live: available`；
- “启动后首次为 Loading，随后变为 Limited”这类不含读数的复现描述；
- App 自己生成并由提交者复核过的隐私安全诊断 JSON。

宽泛产品家族和系统版本不是兼容性保证。只有在多台匿名设备上重复验证后，项目才会更新兼容性结论。
