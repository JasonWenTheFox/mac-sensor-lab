# 02 传感器来源、权限与隐私边界

## 访问级别与就绪状态

v0.3.0 将原先过粗的能力等级拆为 `publicOrdinary`、`publicTCC`、`publicEntitlement`、`undocumentedOrdinary`、`privilegedHelper`、`privateExperimental`、`platformBlocked` 和 `hardwareAbsent`。旧 `SensorCapability` 字段继续保留供向后兼容，但不再用来推断完整权限语义。

硬件存在性、解码器、读取路径、连续数据流和用户功能分别记录在 `readiness`，不得用“检测到服务”代替“已经可以测量”。具体枚举、当前 Provider 矩阵和 schema 见 [`07-硬件清单与能力语义.md`](07-硬件清单与能力语义.md)。

## 数据性质

- **Raw**：接口直接返回，仅做类型/字节解析。
- **Derived**：由 Raw 通过公开公式计算，例如向量模长。
- **Estimated**：缺少计量校准或依赖系统处理，例如近似声级。
- **Calibrated**：用户使用外部参考仪器完成校准，并保存校准元数据。

## 权限策略

- 普通权限探测优先；只在 IOKit 明确返回 `not privileged` / `not permitted` 时显示 `.permissionRequired`。
- `exclusive access`、`busy`、`not ready` 和报告超时属于临时降级，不诱导用户开启无关隐私权限。
- 当前上盖角度和 SPU 环境光读取没有对应的 macOS“隐私与安全性”开关；不要为它们开启相机、麦克风、辅助功能、输入监控或完全磁盘访问。
- 首版不安装 root Helper，不设置 SMC 值，不修改驱动属性。
- 麦克风和定位类功能必须由明确的用户动作启动，并先解释用途。当前只有独立 Sound Input Check 可在二次确认后请求麦克风；Provider 自动采样不得触发 TCC。
- App Sandbox 是否关闭由具体 Provider 决定；公开发布前必须在 README 中醒目标示。
- 权限拒绝后仍允许使用其他 Provider。

## 隐私

用户主动导出的快照、诊断、光照校准和连续记录文件通过目标目录中的 `0600` 临时文件写入、同步并原子替换；创建失败时清理临时文件，不修改目标目录或系统权限策略。

默认不采集或导出：

- 序列号、Hardware UUID、Provisioning UDID；
- 用户名、主机名、账户信息；
- 精确位置；
- 完整进程列表和窗口标题；
- 音频原始录音；
- 网络地址、SSID、BSSID；
- 未经用户选择的长时间传感器记录。

硬件清单只读取非唯一机型类别、长度受限的 SoC/GPU 名称、CPU 核心计数、内存容量、Metal 公开能力和 Touch ID 能力。它不读取序列号、Hardware UUID、Metal registry ID、生物识别录入状态或认证结果；Touch ID 检查不会弹出认证框。

Audio Hardware Provider 只用公开 Core Audio HAL 属性枚举当前可见设备并汇总方向能力，再读取默认输入/输出的固定 transport enum、通道数、标称采样率和 device latency。AudioDevice 数字句柄只在单次读取的局部内存中用于关联默认设备；不读取或导出 device/model UID、名称、厂商、图标、clock domain、驱动自由文本或系统错误文本。此 Provider 路径不创建/启动 IO、不取得 PCM、不调用录音授权，仍属于 `publicOrdinary`。

Sound Input Check 是隔离的会话内 `publicTCC` 实验。它只在用户点击开始、阅读说明并再次确认后，通过 `AVCaptureDevice.authorizationStatus(for: .audio)` 读取四态授权，并且只在 `.notDetermined` 时调用授权请求。获准后才启动 `AVAudioEngine.inputNode` tap；最长五分钟，停止/离页/配置改变/休眠/终止均释放。每个 Float32 buffer 的 channel sample data 仅在音频回调内被检查，并立即归约为受限的 sample rate/channel/buffer/frame 计数、最多 128 个波形分箱、RMS/峰值、dBFS 和最多 128 个正频率相对分箱；必须拒绝非有限值、越界 frame/channel/sample 和异常格式。频谱只在 256…2,048 个最近通道平均帧上去均值、应用 Hann 窗和可复用 DFT setup，最快 10 Hz 更新；当前非 DC 峰值为 0 dB，显示下限为 −80 dB。原始样本不离开回调，不保留、写盘、播放或导出；最多 300 个电平历史点和最近一份频谱只留在面板内存，离页清空，不进入 Provider、Snapshot、Diagnostics 或连续记录。App Bundle 为该功能包含中英文 `NSMicrophoneUsageDescription` 和 Hardened Runtime `com.apple.security.device.audio-input` entitlement；不含定位、相机或其他新权限。dBFS 以数字满刻度 1.0 为基准，不得命名为 dBA/dB SPL/校准响度；最强非 DC 分箱中心不得冒充声源或音高识别。详见 [`11-Audio硬件清单边界.md`](11-Audio硬件清单边界.md)。

E8b 已实现 identity-minimized USB Device Tree：只在用户点击后以普通权限枚举当前 `IOUSBHostDevice` / `IOUSBHostInterface`，只保留有界数字 VID/PID、release、class/interface、current configuration、connection speed、alternate setting 和当次父子关系；结果只存在 Hardware Inventory 面板，离页清空，不进入 Provider、Snapshot、Diagnostics、JSON/CSV、连续记录或持久化。source 按 typed key 逐字段读取并由测试与发布审计锁定，不创建 USB user client。serial/container/ECID/UDID/signature、location/path/entry ID/address、自由文本名称、descriptor blob、内部 power 字段和任何设备 open/transfer/configure/reset 永久或当前明确排除。详见 [`12-USB设备清单边界.md`](12-USB设备清单边界.md)。

E9b 已实现 Camera Capabilities。公开 `AVCaptureDevice.DiscoverySession` 把设备/格式能力发现与真正 capture 分离；只有用户点击后才读取本机 built-in/external 摄像头的当次序号、固定类型/位置/transport 和有界分辨率、帧率、自动对焦、色彩空间能力，并在离页时清空，不进入 Provider 或导出。Info.plist 的独立类型键和 reducer 的 transport 检查双重排除 Continuity Camera，Desk View 也不纳入；source/release audit 拒绝 unique/model ID、名称、厂商、当前活动/配置、Camera TCC、input/session/output 与画面路径。完整边界见 [`13-Camera硬件清单边界.md`](13-Camera硬件清单边界.md)。

E9c 已把 Camera Check 作为独立 `publicTCC` 实验实现。Live 模式每次都先显示隐私解释，第二次确认后才会在 `notDetermined` 时请求 Camera；只有 `authorized` 才创建固定 built-in/external 本机视频 input、单个 session、单个 BGRA data output 与 preview layer。会话最长两分钟，任何停止、离页、休眠、终止、断开、中断、runtime error、异常帧或安全上限都会 fail closed。Raw frame 只在 callback 内以最快 10 Hz、最多 4,096 pixels 规则采样，立即归约为相对数字 luma 与 frame-delivery 统计；不保留图片/缓冲区，不录制、截图、识别、持久化或导出。用途文案和 Camera entitlement 仅为该显式实验服务，不改变 Camera Capabilities 的无 TCC source 边界；真机授权/拒绝和真实画面仍待用户在场验收。

网络 Provider 只读取并相加启用的非回环 BSD 接口计数器。界面和导出不包含接口名、IP、MAC、SSID 或 BSSID；虚拟接口和隧道可能让同一流量经过多个计数路径，所以该值用于观察趋势，不等同于 ISP 账单流量。

独立的 Wi-Fi Radio Provider 只调用公开 CoreWLAN getter，读取当前接口的开关/服务/关联状态、RSSI、noise、channel/width/band、PHY、协商发送速率、发送功率和固定 security enum，并由 RSSI−noise 派生 SNR。0 错误哨兵、未知枚举和越界值省略；接口未报告时硬件存在性保持 `unknown`。它不调用 SSID/BSSID/country/interface identity getter，不读取 MAC/IP/位置，也不扫描或配置网络。

Nearby Wi-Fi Channels 不属于 Provider：只有用户阅读确认说明并再次点击后，才执行一次 `scanForNetworks(withName: nil, includeHidden: false)`，然后立即从每条结果中只提取 `wlanChannel` 与 `rssiValue` 并按频段/信道汇总。它不调用 SSID/SSIDData/BSSID/countryCode/informationElementData 或接口身份，不读取 cached scan results，不注册 scan-cache 事件，不自动重复扫描；最多处理 512 条结果，异常信道/频段丢弃。面板离开后清除结果，Snapshot、Diagnostics、导出和日志都不接收扫描数据。当前实现没有 Location usage description、Core Location 代码或 Wi-Fi Information entitlement；因此也不会为了信道摘要弹出定位授权。Apple 将 SSID/BSSID/country code 访问明确置于 Location Services 授权边界，Access Wi-Fi Information entitlement 文档针对 `CNCopyCurrentNetworkInfo`；这些身份字段没有被 E5b 引入。详见 [`10-Wi-Fi无线电边界.md`](10-Wi-Fi无线电边界.md)。

公开系统电源 Provider 只使用 Apple SDK 文档化的 `IOPowerSources` 接口和固定字段：当前供电类型、内置电池容量/充电状态、系统低电量告警及有效的系统时间估算。它不读取或导出电源名称、Power Source ID、序列号、传输类型或电源适配器元数据；公开 Provider 与未文档化的 AppleSmartBattery 扩展 Provider 分开展示来源和能力等级。

显示 Provider 只使用 CoreGraphics 当前模式中的活动显示器数量、像素尺寸、逻辑 point 尺寸和刷新率；缩放倍率由两组尺寸派生。物理尺实验只在本次 App 运行中用内部 `CGDirectDisplayID` 将窗口当前 `NSScreen` 绑定到会话 slot，界面和公开 state 不包含该 ID；参考长度、校准结果和系统估算均不持久、不导出，也不进入 Snapshot/Diagnostics。它不读取 EDID、厂商、型号、序列号或持久显示器标识，也不调用亮度或显示模式写入接口。

Storage Provider 只使用 Foundation 的公开卷容量资源键，分别保留普通可用、重要用途可用和机会性用途可用的系统语义，并由普通可用容量派生 used。它不读取或导出卷名、卷标识、挂载路径；查询失败时也不回显可能含路径的系统错误文本。

NVMe SMART Provider 通过 Disk Arbitration 只在局部内存中定位当前系统卷的整盘，再沿 IOKit 父链寻找固定的 `NVMe SMART Capable` 布尔属性。它只调用 Apple 公开 `IONVMeSMARTInterface.SMARTReadData`，缓存至少 60 秒，并仅输出固定标量、已知/未知 warning bits 和十组无损 128-bit 累计计数。Raw 计数使用十进制文本且不进入 `Double`；Data Units 的派生字节值是报告单位的检查式换算，不声称为精确历史 I/O 字节数。Provider 不调用 identify、详细 log page 或 self-test，不读取或导出设备名、BSD 名、serial、UUID、registry 路径或系统错误自由文本，也不提供单一“SSD 健康分”。

磁盘活动 Provider 只读取 Apple SDK 公开定义的 `IOBlockStorageDriver` 固定统计字段并做设备级汇总，不读取或导出设备名、序列号、卷名、挂载点或文件路径。累计值属于驱动生命周期，速率属于相邻样本差值。

GPU Provider 只从 `AGXAccelerator` 的 `PerformanceStatistics` 字典读取固定白名单的利用率和内存计数，不枚举或导出 registry 名称、ID、设备身份或其他字典内容。该字典键未公开文档化，跨系统或 GPU 代际缺失时必须返回不可用。

SMC Provider 读取 CPU 品牌字符串后只在内存中归约为 M1–M5 代际枚举，用于选择固定温度 key 表；原字符串、具体机型和任何唯一标识均不进入 Snapshot、诊断或导出。无法识别代际时不猜测未来 key，只尝试固定的代际无关温度、风扇和功耗键。

环境光校准 JSON 只包含 schema 版本及最多 8 组 `rawReference`、`luxReference` 和 `capturedAt`；旧版顶层单点格式仍可读取。导入只接受本地文件，最多有界读取 64 KiB，并拒绝非有限、零值、负值、重复原始值、非单调关系或超量点；校准文件不包含序列号、硬件 UUID、机型或账户信息，也不能证明校准适用于另一台设备。

隐私安全诊断 JSON v3 只包含报告 schema、App 版本、生成时间、Provider 稳定 ID/类别/状态/旧能力字段、domain/access/evidence/readiness，以及通道稳定 ID/单位/数据性质。它刻意省略所有传感器值、显示值、摘要、备注、来源字符串、Snapshot 时间和用户文件路径；运行时还会拒绝非法、重复或机器识别性 ID。完整 JSON Snapshot 从 v0.3.0 起使用 `schemaVersion: 1` 顶层封装，它仍包含真实读数，不得当作隐私安全诊断。

`--demo` 模式只使用仓库内置的确定性 fixture，不读取真实硬件。其 Provider 来源、顶部横幅和 Diagnostics 数据模式始终明确标识 Demo，采样间隔、环境光校准和上盖参考使用独立偏好键。

Force Touch Pressure Lab 使用公开 `NSView.pressureConfiguration` 和 view-local `pressureChange(with:)`。只有用户显式开始后，App 自己的交互区域才接收 `pressure`、`stage` 和 `stageTransition`；不安装 local/global event monitor。0…1 pressure 在每个 stage 内单独归一化，曲线不跨 stage 连接；最多 240 个样本只存在内存中，离页清除，不进入 Provider、Snapshot、Diagnostics、日志或导出。鼠标事件的 `associatedEventsMask` 只用于判断本次输入是否声明 pressure 事件，不读取设备 ID；现有 IOKit Force Touch presence 仅作提示，不单独解锁或阻止实验。

私有 raw contacts、接触面积、逐触点压力和 Trackpad Scale 仍未接入。对 OpenMultitouchSupport 4.0.0 的静态审计发现，现成二进制会读取并日志输出触控板 GUID/DeviceID，且直接链接私有 MultitouchSupport.framework、要求关闭 App Sandbox。因此当前不加载、不分发；未来若继续，只能从可审查源码制作删除设备标识路径的最小 opt-in adapter，并重新评审签名与发布边界。

IOReport 的用户态消费函数由系统库导出，但没有公开 SDK header 或 Apple App 侧文档，因此即使 E3 在一台 Apple Silicon Mac 上证明普通用户可订阅，也归为 `privateExperimental`。当前标准产品不链接该库；未来实验 adapter 只允许精确 group/channel/unit 白名单，任意私有 metadata、topology 名称和未分类 channel 均不得进入 Snapshot、诊断、日志、持久化或导出。详见 [`09-IOReport普通权限可行性.md`](09-IOReport普通权限可行性.md)。

公开兼容性贡献只接受宽泛机型类别、系统版本、Provider 状态和经提交者人工复核的隐私安全诊断。完整 Snapshot/CSV、连续记录、系统转储和真实读数不应进入公开 Issue；详细流程见 [`06-匿名兼容性贡献指南.md`](06-匿名兼容性贡献指南.md)。

任何未来遥测必须默认关闭，并在单独设计和审核后再加入。

`PrivacyInfo.xcprivacy` 随 App Bundle 一起打包，当前声明不跟踪、没有 tracking domain，也不把任何数据发送到设备外。Apple 当前在 [Privacy manifest files](https://developer.apple.com/documentation/bundleresources/privacy-manifest-files) 中要求所有平台描述数据收集，同时在 [Describing use of required reason API](https://developer.apple.com/documentation/bundleresources/describing-use-of-required-reason-api) 中把 Required Reason API 声明范围列为 iOS、iPadOS、tvOS、visionOS 和 watchOS；本 macOS-only 构建不虚构对应 reason code，若未来增加这些平台则必须重新审计。

## 准确性边界

- 环境光原始通道不自动等同于 lux；
- 单点环境光校准只是在假设零偏移下按用户外部参考缩放；2–8 点模式是显示 RMSE 的线性最小二乘拟合，并会在样本范围外外推。两者产出都必须标为 `Estimated`，不能标为 Apple 校准值或认证计量结果；
- dBFS 不等同于 dB SPL/dBA；
- 芯片/电池内部温度不等同于环境温度；
- Foundation 的 thermal pressure 是离散系统状态；0–3 只用于排序和趋势显示，等级间距不是温度、百分比或线性物理量；
- 报告满充容量 ÷ 设计容量只是控制器字段的派生比例，可能在新电池上超过 100%，不等同于 Apple 的“电池健康”状态或实验室容量测试；
- 电池剩余/充满时间是控制器动态估算；`65535` 等不可用哨兵值必须省略，不能当作分钟显示；
- Battery Trend 是最近内存采样窗口的线性趋势，不是 Apple 的系统续航预测；短时工作负载、休眠、接通电源或电量控制器取整都可能使它失效；
- IOReport/芯片能量估算不等同于墙插整机功率；
- IOReport 的 energy delta 可派生采样窗内 Estimated W，但 ANE power 不是 utilization、state index 不是 MHz、未分类 channel 不是可发布事实；
- AGX 驱动利用率不保证与 Activity Monitor 的采样窗口、归一化或显示值一致；
- Wi-Fi transmit rate 是当前协商 PHY 速率，不等同应用吞吐量；RSSI/noise 只描述当前无线电链路，不直接给出距离或频道拥塞；
- 无磁力计的 yaw 会漂移；
- 触摸板称重受电容接触、位置、温度和机型影响；
- 私有 API 可能随 macOS 更新变化。
