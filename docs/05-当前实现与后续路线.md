# 当前实现与后续路线

更新：2026-09-11

## 已交付的首个垂直切片

当前仓库可以使用 Swift Package Manager 构建原生 macOS App、探针 CLI 和无测试框架自检 CLI。App 先显示 SwiftUI 外壳，再并发加载 Provider；自动刷新可选择 1、2、5 或 10 秒，并只为绘图/派生通道保留最多 256 条序列、每条 600 个严格递增时间戳的内存历史点。

当前包含 26 个 Provider：原有的系统、性能、GPU 性能、聚合网络/磁盘、电池/电源、热压力、只读 SMC、显示、存储、SPU、上盖角度和实验硬件，以及 Mac 机型类别、Apple SoC、CPU 拓扑、内存硬件、Metal GPU、Touch ID、公开 Core Audio 设备清单、每显示器能力、系统盘介质属性、NVMe SMART 标量/累计计数和当前 Wi-Fi 无线电链路。数据模型保留稳定 ID、来源、单位、Raw/Derived/Estimated/Calibrated，并将导航类别、硬件领域、访问级别、兼容性证据和五段就绪状态分别表达。

## 本机验证结果

- Swift 6.3.3 Command Line Tools 构建通过；
- `sensorlab-selftest` 使用可复用数据契约审计验证 Provider/Snapshot 稳定 ID、唯一性、注册元数据一致性、时间戳、有限值、隐私字段和 JSON/CSV 有效性；
- 本机隐私安全真机探针验证 26 个 Provider 均完成读取，其中 24 个 Available、2 个 Limited；Wi-Fi Radio 与 Audio Hardware 均为 Available，诊断只显示固定状态和通道 ID，不包含读数、网络/接口身份或音频设备身份；
- 当前 XCTest 套件共 166 项，包含能力语义、硬件字符串/计数边界、Demo/live 同序同语义、JSON/Diagnostics schema、中文本地化、NVMe SMART 解码/失败/缓存/UInt128 极值、IOReport 无值 metadata/delta、显示校准数学/绑定失效/窗口切屏/旋转轴/布局边界、Pressure Lab 值域/分段/有界历史、Wi-Fi radio/scan 边界、Audio Hardware 身份/采集 API 排除、USB tree 与 Camera Capabilities reducer/source/lifecycle，Sound Input Check 二次确认/四态授权/PCM 与频谱边界，以及 Camera Check BGRA reducer、每次二次确认、四态 TCC、会话时限、迟到回调、生命周期停止、失败映射、source allowlist 与 Demo 清空；
- Hardware Inventory 页将九个非唯一硬件事实 Provider 从 Overview 中独立展示，并可展开卡片查看全部事实；卡片和 Raw Sensors 显示 domain/access，Raw Sensors 进一步显示 evidence 和五段 readiness；
- 完整 Snapshot JSON 使用 schema v1 顶层封装，隐私安全 Diagnostics 升级为 schema v3，CSV 表头也包含新语义列；旧 capability 与所有旧 Provider/Channel ID 保留；
- App 打包、Info.plist 校验和 ad-hoc 签名通过；
- GitHub Actions 保留 `macos-26` 的完整验证流程，但仅允许手动触发，普通 push/Pull Request 不自动消耗运行分钟；
- SwiftUI 的 Overview、Raw Sensors、Experiments、Diagnostics 四页已做可访问性树回归；Experiments 的显示器物理尺已在真实 App 中核验当前屏幕 slot、逻辑/像素模式、系统估算对照和可访问控件，未用虚假参考触发校准；Pressure Lab 已核验 detected/start/unsupported-input/stop/离页清理和 Demo 禁用路径，真实 pressure 流仍需用户用物理 Force Touch 手势验收；Sound Input Check 的非 TCC Demo 路径由 fixture 验收，真实首次授权和 PCM 流故意留给用户在场。
- 电池、SMC 温度/风扇/功耗、上盖角度和环境光在本机得到真实读数；
- SMC 温度 key 已按 M1–M5 代际分层，并由五代匿名 fixture 与未知代际失败路径验证；非唯一 CPU 品牌只用于内存内选表，不保留或导出。
- SPU 环境光单进程连续 20 次和双进程各连续 20 次读取均成功；
- SPU 打开错误现在区分权限拒绝和临时争用；短暂缺报最多保留 12 秒的最近成功样本，且不伪造新时间戳；
- SPU 加速度计/陀螺仪在系统不发布报告时安全降级，没有写入驱动属性；
- Xcode 首次组件初始化已完成，本机完整 XCTest 套件通过；默认发布验证完全离线，不依赖 GitHub Actions。
- 自动采样支持暂停/恢复和内存历史清空；连续 CSV 记录包含原始值与格式化值，逐批同步并有 50 MB 硬上限。
- Light Meter 提供原始值滚动统计和可选 1–8 点 Estimated lux；单点保留零偏移比例，多点使用归一化线性拟合、显示 RMSE 并支持撤销最后一点。Light Spectrum 将四个未知响应通道归一化为相对比例，可保存本地光型参考并显示有界相似度和最大偏移，但不宣称色温、波长或 lux。Lid Protractor 提供本地参考角度与相对变化。
- Light Meter 校准可由用户主动导入/导出为不含设备标识的 JSON；导入时重新执行有限正数、严格单调、数量和 schema 验证，并兼容旧版单点格式。
- 原生 UI 已通过中央 `L10n` 层和 String Catalog 支持英文/简体中文；白名单展示适配器覆盖动态摘要、通道标签、枚举值、单位和项目自有说明，本地化不改变 Provider/Channel ID、JSON/CSV 字段或原始读数。
- Overview 在传感器卡片前汇总当前 Provider 的 Available、Loading、Limited、Permission required、Unavailable 和 Error 数量，并保留本次启动的状态切换总数；当前异常可直接进入 Raw Sensors，间歇性切换可进入 Diagnostics 查看逐 Provider 计数。
- Computer Use 回归验证了暂停/恢复、校准输入、派生通道、上盖参考交互，以及公开 Pressure Lab 未把私有 Trackpad Scale 误解锁；临时测试校准均已清除。
- 系统性能 Provider 使用相邻 Mach CPU tick 计算汇总利用率，并公开负载、内存页分类和 swap；不采集进程列表。
- 网络吞吐量 Provider 使用相邻 BSD 聚合计数器计算上下行字节与包速率；不导出接口名、地址、SSID、BSSID 或 MAC 地址，并明确提示虚拟/隧道路径可能重复计数。
- 磁盘活动 Provider 使用 `IOBlockStorageDriver` 固定统计字段计算聚合读写吞吐量和操作速率；不读取设备名、序列号、卷名或文件路径。
- Dashboard 采用唯一窗口，避免多个生命周期任务同时轮询硬件；关闭窗口会安全结束连续记录。
- App Bundle 包含并校验不跟踪、不联网收集数据的 `PrivacyInfo.xcprivacy`。
- Raw Sensors 可本地搜索 Provider、通道、来源、状态、硬件领域、访问级别、兼容性证据、就绪状态和稳定 ID，通道命中只过滤显示副本，不改变采样或导出。
- 工具栏与 Settings 共用并持久化采样间隔，但暂停状态每次启动重置；Overview 以动态相对时间显示原始样本年龄，Raw Sensors 显示每个 Snapshot 的真实时间戳，短暂缓存的降级样本不会伪装成新读数。
- 电池 Provider 的固定白名单包含设计容量、报告满充容量和有效的控制器时间估算；容量比例明确标为派生值且不冒充 Apple 的 Battery Health。
- 独立的公开 `IOPowerSources` Provider 已在本机返回 Available，仅使用受支持的供电、容量、充电、系统低电量告警和时间估算字段，并明确忽略名称、ID、序列号、传输与适配器元数据。
- Display Provider 已按 CoreGraphics 定义区分当前模式的 pixels 与 points，并仅在横纵倍率一致时给出 Derived backing scale；不读取 EDID、厂商、型号、序列号或持久显示器标识。
- Experiments 新增 Battery Trend：只在公开电量历史满足 5 分钟、4 样本、可测下降和明确放电状态后显示观察耗电率与 Estimated 耗尽时间；充电、接通电源或弱/异常窗口安全等待。
- Storage Provider 改用 Foundation 公开卷资源键，分别展示普通/重要用途/机会性可用容量并安全派生 used；不采集卷名、标识或挂载路径，失败时不回显系统错误自由文本。
- Thermal Provider 保留公开离散状态并新增 0–3 Derived ordinal；Thermal Trend 用有界历史展示近期最高状态和切换次数，同时明确不推断温度或线性物理间距。
- Component Thermals 与 System Power Trend 只复用现有只读 SMC 白名单，分别对比 CPU/GPU 热点有界历史、显示系统内部功耗的近期平均值和峰值；不把结果宣传为环境温度或插座功率。
- Network Throughput 与 Disk Activity 实验分别保留汇总收发和读写的双通道有界历史，显示近期均值与双曲线；不增加任何接口、地址、设备、卷或路径字段。
- Wi-Fi Radio 通过公开 CoreWLAN getter 输出当前链路的 RSSI/noise、派生 SNR、频道/宽度/频段、PHY、安全模式、协商发送速率和发送功率；Wi-Fi Signal 实验显示有界双曲线和当前逐字段事实。Provider 本身不扫描网络；协商 PHY 速率不是应用吞吐量。
- Nearby Wi-Fi Channels 只有用户二次确认后才执行一次公开 CoreWLAN 非定向扫描，并立即把最多 512 条结果缩减成频段、信道、报告记录数、RSSI 与带宽。它不访问网络/接入点/接口身份、国家代码、信息元素或位置，不请求 TCC/entitlement，不读取缓存、不后台运行，也不进入 Snapshot/Diagnostics/导出；20 秒 watchdog 和停止按钮只停止等待并丢弃迟到结果，底层阻塞调用返回前始终保持单飞，返回后冷却 10 秒。
- Audio Hardware 使用公开 Core Audio 属性汇总设备/输入/输出/双工数量，并读取当前默认输入/输出的固定 transport、通道数、标称采样率和 device latency。AudioDevice 句柄只在一次读取内关联默认设备；不查询 UID/model UID/名称/厂商，不创建或启动 IO，不采集 PCM、不录音、不请求麦克风权限。合法 0-buffer 单向配置、默认设备缺失、局部属性失败和设备切换均有 fixture；完整边界见 [`11-Audio硬件清单边界.md`](11-Audio硬件清单边界.md)。
- Sound Input Check 作为独立 `publicTCC` 面板完成 E7b…E7d：仅用户二次确认可在 not-determined 时触发麦克风授权，授权后的 `AVAudioEngine` tap 最长五分钟，停止/离页/配置变化/休眠/终止都释放。Float32 PCM 只在回调内被即时缩减为采样率/通道/计数、最多 128 个通道平均波形分箱、全通道 RMS/峰值和以 1.0 为满刻度的 dBFS，电平历史最多 300 点。会话内可复用 Accelerate DFT setup 对 256…2,048 帧去均值 Hann 窗口做最快 10 Hz 的相对频谱，输出最多 128 个正频率带、当前峰值 0 dB 和 −80 dB 显示下限。原始样本不离开回调，不录制/写盘/导出；派生值不进入 Provider/Snapshot/Diagnostics，离页清空。dBFS 不是 dBA/dB SPL/校准响度，最强非 DC 分箱中心不是声源/音高/语音/环境识别。用途文案和 Audio Input entitlement 均由发布审计和 App 验签固定。
- E8b 已实现 identity-minimized USB Device Tree：普通未签 entitlement 的读取只枚举 `IOUSBHostDevice` / `IOUSBHostInterface`，逐个访问公开 typed numeric allowlist，以最多 128 个 device、512 个 interface 和 32 层父链构造当次 preorder ordinal。Hardware Inventory 仅在用户点击后读取一次，约两秒后停止等待并丢弃迟到呈现，底层返回前保持单飞，离页清空；Demo 只用合成 simple/hub/composite fixture。它不注册 Provider、不进入 Snapshot/Diagnostics/导出/持久化，也不创建 USB user client。USB version/power、身份/位置/自由文本、descriptor 与任何 device open/control/configure/reset 均不在实现范围。完整字段和威胁模型见 [`12-USB设备清单边界.md`](12-USB设备清单边界.md)。
- E9b 已实现 Camera Capabilities：用户主动、session-only 的公开 AVFoundation discovery 只归约本机 built-in/external 相机的固定类型/位置/transport、format count、encoded dimensions、fps、autofocus 和 color space。`NSCameraUseContinuityCameraDeviceType=true` 与 Continuity transport 双重排除附近设备；两秒等待边界、单飞、迟到丢弃、离页清空、合成 Demo 和 source/release audit 已接入。清单 source 本身不请求 Camera TCC、不打开设备或创建 capture，也不读取 identity/free-text。详见 [`13-Camera硬件清单边界.md`](13-Camera硬件清单边界.md)。
- E9c 已实现独立 Camera Check：每次 live 运行均需二次确认，not-determined 只在确认后请求 Camera；capture 只用固定本机输入、`.medium/.low` preset、单一 BGRA output 与 preview。`startRunning` 在后台串行队列，会话最长两分钟，停止/离页/休眠/终止/断开/中断/错误/异常帧均释放；raw frame 只在 callback 内最快 10 Hz、最多 4,096 pixels 抽样并立即归约，不录制、截图、识别、写盘、上传、持久化或导出。English/中文用途文案、Camera entitlement、source/release/signature audit、pure reducer/model fixture 和合成 Demo 已完成；真实授权/拒绝和画面验收待用户在场。
- Force Touch Pressure Lab 由用户显式开始，只在 App 自己的交互区接收公开 AppKit pressure 事件；它显示 stage-local 0…1 值、stageTransition、分段曲线和 stage 2 进入次数，最多保留 240 个内存样本，离页清空，不读取 raw contacts/device ID，也不持久化或导出。
- GPU Provider 从 AGX 性能字典只读取固定白名单的 Device/Renderer/Tiler 利用率和 GPU 内存计数；本机可用，其他机型缺键时安全降级。
- Diagnostics 可由用户主动导出值域最小化的支持 JSON；报告不含传感器读数、自由文本、来源字符串或路径。
- 连续 CSV 的样本去重在 Recorder actor 内串行执行，避免初始 flush 与自动刷新并发时重复写入。
- CI 运行项目范围的 release audit，检查已跟踪产物、用户绝对路径、密钥特征、权限用途键、危险写入 API、许可证和 Privacy Manifest 一致性。
- CI 同时编译 Debug 与优化后的 Release 产品，并用 Release 可执行文件组装、lint 和严格验签临时签名的本地 App Bundle。
- Release App 的 ad-hoc 签名已启用并验证 Hardened Runtime；确定性 Demo 在强化运行时下可启动存活，尚待正式 Developer ID 身份和公证复验。
- App Bundle 改为在 `outputs` 同文件系统的全新暂存目录组装、校验和签名后再替换旧生成包；回归测试确认人为加入的陈旧资源不会跨构建残留。
- 新增离线 `scripts/verify-local.sh` 统一入口，默认复现主要 CI 检查且不连接 GitHub；真机契约、ASan/TSan 和 SPU 稳定性检查均通过显式参数启用。
- 显式 `--demo` 模式提供与 live registry 数量一致的确定性 fixture；全界面标识非实时数据，并隔离采样与校准偏好。
- `README.en.md` 提供面向公开首发的完整英文能力、构建、安全、隐私和限制说明，并与中文 README 互链。
- 环境光校准导入使用最多 64 KiB 的本地文件有界读取，超限或非法数据不会替换当前校准。
- CSV 文本列会转义公式起始字符和 CR/LF，同时 `raw_value` 保持可供机器读取的数值单元格。
- Probe CLI 支持确定性 `--demo` 和无读数 `--diagnostics`，同时保留无参数真实完整快照行为。
- SensorCore 提供独立的结构化数据契约审计；本机真实 Provider 和确定性 Demo registry 均已通过，恶意/损坏 fixture 覆盖非法 ID、元数据漂移、非有限值、空字段和未来时间戳失败路径。
- Provider 并发读取与 Dashboard 排序使用首个注册位置构造非陷阱映射；重复 ID 会保留给契约审计明确失败，而不是先触发 `Dictionary(uniqueKeysWithValues:)` 崩溃。
- 网络和磁盘速率样本记录参与聚合的接口/设备数量；拓扑计数变化或时间无效时重新建立基线，避免把新加入计数器误算成吞吐量峰值。
- 电池 Provider 不再把缺失的来源/充电/满充字段当成 `false`；异常容量百分比、非有限电压电流和溢出功率会被省略而不是包装成事实。
- 所有持久偏好键由 `SensorPreferenceKeys` 统一生成；Demo 的采样、光照校准和上盖参考均带独立后缀，不能读取或覆盖 live 状态。
- 光照校准比例、滚动统计平均/相对位置和上盖相对角度采用溢出安全计算；即使每个输入单独有限，非有限派生结果也会被拒绝。
- 连续 CSV 在每批写入前重新 `seekToEnd` 并以实际文件偏移复核 50 MB 上限；录制期间的外部追加不会被覆盖，也不能绕过容量保护；文件被截断到缺少表头时安全停止。
- 隐私安全诊断导出在运行时复用契约审计，拒绝非法、重复或机器识别性 Provider/通道 ID；隐私承诺不再只依赖发布前自检。
- Dashboard 在内存中保留无读数的采样健康计数，显示刷新次数/最近耗时和 Provider 状态切换，并可随隐私安全诊断导出；同一周期重复 ID 不会放大计数，跨周期状态最多跟踪 256 个 Provider。
- Dashboard 历史只保存当前图表和派生实验使用的通道，总计最多 256 条序列、每条 600 点；重复/倒退时间、非有限值和超长 ID 会被忽略。
- 快照、诊断、光照校准与连续记录统一通过目标目录中的 `0600` 临时文件同步并原子替换；失败路径清理临时文件，不修改目录或系统权限策略。
- Dashboard 按注册索引回填 Provider 结果，并在进入 UI、历史与记录前通过 fail-closed Snapshot Gate；畸形负载只产生固定 Error Snapshot，不会被回显或借变化 ID 扩大状态数组。
- 连续记录器自身也在构造去重键和 CSV 行前验证 Snapshot 契约，并把跨批次去重状态限制为 256 个 Provider；达到上限后仍允许已有 Provider 更新，但原子拒绝新 ID。
- 连续记录停止时重新读取真实文件末尾，最终进度不会遗漏最后一次外部追加；同步、定位或关闭失败时也先把 Recorder 转换为关闭状态。
- Snapshot 未来时间容差只接受有限非负值；负数、非有限或加法溢出的容差按零处理，不能关闭未来时间检查。
- Provider 契约审计累计到 4096 条 Issue 后停止后续字段扫描，返回结果最多 4096 条；高密度畸形通道不能继续扩大错误数组。
- CPU tick、Mach page、网络/磁盘/GPU 累计计数、SMC 风扇数量、采样耗时和字节速率格式化均使用检查式算术；极端损坏值只会被省略或使 Provider 降级，不会触发 Swift 溢出陷阱。
- GPU 内存与磁盘驱动的 `NSNumber` 计数现在只接受精确非负整数；负值、小数、非有限或超范围载荷不会经 `uint64Value` 绕回成巨大读数。
- 连续 CSV 先逐行计算整批 UTF-8 大小并完成容量预检，再逐行编码和写入；容量不足时文件仍只有原内容，容量足够时不再额外保留整批 Data 副本。
- Provider 契约现在限制 Provider/通道/备注数量及 ID/显示文本长度，并拒绝空展示元数据、重复备注、读取完成后残留 Loading 和 Available 空通道；超长字符串只检查固定前缀，不参与哈希、大小写转换、元数据比较或错误消息。
- Diagnostics 将权限不足、不可用、错误、受限和加载状态分开计数；Settings 明确现有 live Provider 会在采样时尝试普通只读访问，被 macOS 拒绝时只降级且不提权或绕过。
- Experiments 将原先容易误解的 Vibration Recorder 改为低速 Motion Trend，显示 RMS 变化量和峰峰值，并明确 1–10 秒采样不能测量振动频率；未就绪卡片显示具体依赖状态。
- 每个 Provider 经过默认 2 秒的单飞协调门；单个同步系统调用阻塞时只使该 Provider 降级，不再卡住整页刷新，也不会在原调用结束前叠加重复读取。
- SMC 与上盖角度现在按系统打开结果区分设备缺失、权限拒绝、临时争用和普通错误；Lid Protractor 的显示范围与 Provider 的 0–360 度契约一致。
- 显示硬件 Provider 通过 CoreGraphics/AppKit 提供本次会话顺序的模式、色域、EDR、帧率和 Estimated 物理尺寸/PPI；最高像素模式会纳入当前模式，不因 API 枚举不完整而产生自相矛盾。
- 系统存储硬件 Provider 通过 Disk Arbitration 输出经白名单化的整盘介质属性，不保留型号、序列号、UUID、名称或路径，也不猜测 SMART 健康。
- E2e 已实现 session-only Display calibration core：只在当前运行中用内部 `CGDirectDisplayID` 绑定显示对象，对外只给出 slot、generation/revision、mode geometry 和用户参考结果；topology 增删/重排清空全部校准，对应 pixels/points/rotation/backing scale 变化只清空该 slot。旧 context 不会因模式切回原值而重新有效，非法输入也不会覆盖已有校准。该 core 不进入 UserDefaults、文件、Snapshot 或导出，最小水平 ruler UI 留在 E2f。
- E2c/E2d 已实现 `storage.nvme_health`：只针对当前系统卷整盘调用 Apple 公开 `IONVMeSMARTInterface.SMARTReadData`，分别展示 warning bits、综合温度、备用空间/阈值、可超过 100% 的寿命消耗估算和十组 128-bit 累计计数。Raw 计数使用两个 UInt64 limb 和无损十进制文本，`value` 保持为 `nil`；Data Units 以检查式×512,000 生成独立 Derived 计数字节值，不冒充精确历史 I/O。读取至少缓存 60 秒，固定区分缺失、接口、权限、忙碌和失败状态，不读取 identify、serial、型号、路径或详细日志，也不产生单一“SSD 健康分”。
- E3 已核验 IOReport 普通权限边界：一台 Apple Silicon 测试机上，CPU complex/core residency 与 Energy Model 的精确白名单均可在 100/500/1000 ms 生成 delta，五次发现结构一致；但用户态消费 API 没有公开 header/文档，Standard 产品不链接私有库，也没有新增正式 Provider。
- E3 的纯 Swift policy 只接受两个 CPU state group 和 CPU/GPU/ANE/DRAM/PCI energy 候选，丢弃原始 metadata；delta math 会拒绝负值、非法时间和溢出。频率、Media Engine、bandwidth、SoC total 与 ANE utilization 不以猜测值交付。

真实数值不写入仓库文档，以免把一次性机器状态误当成固定测试结论。

## 安全与隐私不变量

1. 不以 root 运行整个 App；
2. 不调用 sudo，不修改 Apple SPU 驱动属性；
3. SMC 目标中不存在写 key 或风扇控制方法；
4. 仅查询固定白名单的电池字段；
5. 不采集序列号、硬件 UUID、主机名、用户名、网络标识、位置、进程列表或录音；Sound Input Check 的 PCM 样本只在音频回调内即时归约，不保留或导出，派生值有界且离页清空；
6. 只有用户主动使用导出或连续记录按钮时，数据才会写入用户选择的 JSON/CSV 文件；
7. 未校准的环境光、姿态或称重值不会包装为计量结果。
