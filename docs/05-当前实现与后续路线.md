# 当前实现与后续路线

更新：2026-08-20

## 已交付的首个垂直切片

当前仓库可以使用 Swift Package Manager 构建原生 macOS App、探针 CLI 和无测试框架自检 CLI。App 先显示 SwiftUI 外壳，再并发加载 Provider；正常运行时每两秒刷新一次，并为明确挑选的动态通道保留最多 60 个历史点。

首版包含 10 个 Provider：系统、电池、公开热压力、只读 SMC、显示、存储、SPU 存在性、SPU 实时报告、上盖角度和实验硬件能力。数据模型始终保留稳定 ID、来源、单位、原始/派生类别、能力等级、状态、时间戳和限制说明。

## 本机验证结果

- Swift 6.3.3 Command Line Tools 构建通过；
- `sensorlab-selftest` 验证 Provider 唯一性、真实可用数量、范围、有限值、隐私字段和 JSON/CSV 有效性；
- App 打包、Info.plist 校验和 ad-hoc 签名通过；
- GitHub Actions 使用 `macos-26` 执行格式、构建、XCTest、portable 自检与 App Bundle 验证；
- SwiftUI 的 Overview、Raw Sensors、Experiments、Diagnostics 四页已做可访问性树回归；
- 电池、SMC 温度/风扇/功耗、上盖角度和环境光在本机得到真实读数；
- SPU 加速度计/陀螺仪在系统不发布报告时安全降级，没有写入驱动属性；
- 完整 XCTest 已编写，但本机完整 Xcode 首次许可尚未由用户接受，因此暂未运行。

真实数值不写入仓库文档，以免把一次性机器状态误当成固定测试结论。

## 安全与隐私不变量

1. 不以 root 运行整个 App；
2. 不调用 sudo，不修改 Apple SPU 驱动属性；
3. SMC 目标中不存在写 key 或风扇控制方法；
4. 仅查询固定白名单的电池字段；
5. 不采集序列号、硬件 UUID、主机名、用户名、网络标识、位置、进程列表或录音；
6. 只有用户主动使用导出按钮时，数据才会写入用户选择的 JSON/CSV 文件；
7. 未校准的环境光、姿态或称重值不会包装为计量结果。

## 下一阶段

### P0：完成标准开发环境

- 用户本人接受 Xcode 许可；
- 运行 `swift test`；
- 建立正式 App target、Development 签名和 Release 配置；
- 确认正式产品名和 Bundle ID。

### P1：强化可靠传感器

- 把 SMC key 白名单按 Mac 型号分层，并加入非本机 fixture；
- 为电量、温度、风扇、功耗、开合角提供可选择采样频率；
- 增加暂停、清空历史、CSV 连续记录和最大文件保护；
- 给环境光建立“原始强度”曲线和外部照度计校准流程。

### P2：权限型与私有接口实验

- 在明确的用户操作后加入麦克风声压/频谱 Provider，并使用系统权限说明；
- 独立审计 OpenMultitouchSupport 二进制来源、checksum、签名与私有框架影响后，再决定是否接入 Force Touch；
- 若未来确需特权能力，使用最小特权 Helper 设计评审，绝不让主 App 以 root 运行。

### P3：开源发布

- 建立 GitHub 仓库和 CI；
- 添加多型号匿名诊断贡献流程；
- 完成英文首发文档，再集中引入 String Catalog 做中文等本地化；
- 在 Developer ID、Hardened Runtime、Notarization 和隐私清单齐备后发布可下载构建。
