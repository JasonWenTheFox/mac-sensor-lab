# 04 验收与发布标准

## 代码质量

- Swift 编译无错误；
- 核心模型和导出有单元测试；
- Provider 错误不会导致 App 崩溃；
- 资源释放和取消路径可验证；
- 关闭唯一 Dashboard 窗口会取消采样循环，并安全结束活动中的连续记录；
- 代码中不包含密钥、真实设备唯一标识或本机绝对私密路径。
- 英文/简体中文界面键由同一 String Catalog 管理，生成的 `.lproj` 必须与 Catalog 同步，所有代码中的静态本地化键必须有对应目录项。

## 功能验收

- 冷启动先显示 UI，再更新传感器；
- Refresh 可重复运行，不累积重复任务；
- SPU 短暂争用不会误报权限，最近样本保留原时间戳且不重复写入历史曲线；
- 至少一个公开 Provider 返回真实数据；
- 不支持/无权限 Provider 显示明确原因；
- Provider health 汇总必须把 Permission required、Unavailable 和 Error 分开计数；设置页不得把自动采样的只读 HID Provider 错称为 opt-in；
- JSON/CSV 导出字段稳定、单位明确；
- Raw Sensors 搜索可命中 Provider、通道、来源、状态、稳定 ID 和当前语言的已本地化显示名称；通道级命中只缩小显示，不改变导出快照；
- 连续 CSV 的表头只写一次，原始值与格式化值分列，每批数据同步到磁盘；
- 每批连续记录必须先重新定位实际文件末尾并按真实大小复核上限；外部追加不得被后续采样覆盖或绕过 50 MB 保护；
- 连续记录必须先完成整批 UTF-8 大小预检，容量不足时不能写入部分行；容量足够时逐行编码/写入，避免额外保留整批 Data；
- 录制目标被外部截断到缺少完整 CSV 表头时必须安全停止，不得继续写入无表头行；
- CSV 文本列必须防止表格软件公式解释并完整处理 CR/LF；数值 `raw_value` 列不得因此失去数值语义；
- 初始记录刷新和自动刷新并发时，同一 Provider 的相同时间戳/状态只能写入一次；同时间戳发生状态变化时仍需保留该变化；
- 连续记录必须在构造去重键或 CSV 行之前拒绝违反 Snapshot 契约的整批输入，跨批次去重状态最多跟踪 256 个 Provider；达到上限后已有 Provider 仍可继续记录，新 ID 必须整批拒绝且不写入；
- 连续记录停止时必须重新读取真实文件末尾作为最终字节数，并在抛出同步、定位或关闭错误前先把 Recorder 状态转换为已关闭；
- 暂停不禁用手动刷新，清空历史不删除文件，记录达到 50 MB 前安全停止；
- 快照、诊断、校准和记录文件必须通过目标目录中的 `0600` 临时文件同步并原子替换；替换已有宽权限文件后仍须为仅当前用户读写，失败不得遗留临时文件；
- 图表历史只缓存已声明的绘图/派生通道，最多 256 条序列且每条 600 点；重复、倒退、非有限时间和值或超长 ID 不得进入缓存；
- 采样间隔在重启后保留，暂停状态在重启后恢复为自动采样；Raw Sensors 显示 Snapshot 原时间戳；
- 环境光校准前不出现 lux；校准后派生通道标为 Estimated，清除校准后立即从 UI 和后续导出消失；
- 环境光校准接受 1–8 个有限正数且严格单调的 raw/lux 点；多点模式必须使用溢出安全的归一化线性拟合并展示 RMSE，支持撤销最后一点；
- 环境光校准 JSON 可由用户主动导入/导出；只接受最多 64 KiB 的本地文件，无效、非有限、零值、负值、重复、非单调或超量输入必须被拒绝，失败导入不得替换当前校准，旧版单点 JSON 必须保持可读；
- 光照比例、滚动统计和相对角度等派生运算必须再次验证结果有限；有限输入发生算术溢出时不得生成通道或显示值；
- Motion Trend 的均值、RMS 变化量和峰峰值必须忽略非有限输入并保持结果有限；UI 必须声明 Dashboard 采样率不能测量振动频率；
- Thermal Trend 必须保留原始 Nominal/Fair/Serious/Critical 文本，序数通道只能接受 0–3 整数和严格递增时间戳；近期最高状态与切换次数必须来自有界历史，并明确声明序数间距没有物理意义、不能解释为温度；
- 网络收发与磁盘读写实验必须分别保留两条有界速率历史；平均值和曲线只能来自有限的汇总速率，且不能引入接口、地址、设备、卷或路径身份；
- 硬件存在性 Provider 不能单独解锁需要真实连续数据的实验；
- CPU 利用率必须由两个相邻 tick 样本计算并限制在 0...100%，首个样本只建立基线；
- GPU/Renderer/Tiler 利用率必须限制在 0...100%，只读取固定键；缺少键时不得制造 0% 读数；
- 网络速率必须由两个单调计数器样本计算；计数器回退、非有限时间或活动接口数量变化时重新建立基线，且任何输出不得包含接口名或网络地址；
- 磁盘速率必须由两个单调驱动计数器样本计算；计数器回退、非有限时间或设备数量变化时重新建立基线，且任何输出不得包含磁盘、卷或路径标识；
- 电池容量比例必须保留设计容量与报告容量原始通道；不可用时间哨兵不得进入 UI 或导出通道；
- 缺失的电源来源、充电或满充布尔字段必须保持未知并省略，不得伪造成 `Battery` 或 `No`；充电百分比与电功率只接受有限且物理边界有效的输入；
- 公开 `IOPowerSources` Provider 只接受 AC/Battery/UPS 三种固定供电类型和 None/Early/Final 三种系统低电量告警，不得回显未知系统字符串或整数；负数哨兵、非有限或超出 24 小时的时间估算必须省略，不得读取电源名称、ID、序列号、传输或适配器元数据；
- Battery Trend 只保留有界公开电量历史，并且仅在当前来源明确为 Battery、充电明确为 false、至少 4 个严格递增样本跨越 5 分钟且净下降至少 0.5 个百分点时估算；明显回升必须重置窗口，非有限、越界、倒序、弱变化或超过合理值域的结果必须省略；
- 显示 Provider 必须区分 CoreGraphics 当前模式的 pixels 与 points，缩放倍率只在横纵比一致且值域合理时作为 Derived 输出；无效尺寸、零值、非有限或异常刷新率必须省略，不得读取 EDID、厂商、型号、序列号或持久显示器标识；
- Storage Provider 必须把普通、重要用途和机会性可用容量保留为不同通道；负数、零总容量或超过总容量的字段必须省略/降级，used 只能由有效 total 与普通 available 派生；不得读取/导出卷名、卷 ID、挂载路径或回显系统错误自由文本；
- 诊断支持报告必须可解析并包含 Provider 状态，但不得包含原始/格式化传感器值、摘要、备注、来源字符串或 Snapshot 时间；
- 采样健康统计必须忽略同一周期的重复 Provider ID，跨周期最多跟踪 256 个 Provider，并只导出刷新次数/耗时、状态切换和连续异常计数；
- 隐私安全诊断服务遇到非法、重复或机器识别性 Provider/通道 ID 时必须拒绝导出，不能只依赖 CI 提前发现；
- Demo 模式 Provider 数量必须与 live registry 一致、所有数值有限、来源固定为 fixture，并在每个页面持续显示非实时横幅；采样、光照校准和上盖参考偏好键不得与 live 模式重叠；
- Probe CLI 的 `--demo` 保持 Provider 顺序，`--diagnostics` 不含读数/自由文本，未知参数必须非零退出；
- Provider 数据契约审计必须拒绝非法/重复/识别性稳定 ID、注册元数据漂移、重复通道、非有限值、空白显示值或显式单位，以及明显来自未来的时间戳；
- Provider 时间戳审计的未来容差只接受有限非负值；负数、`NaN`、Infinity 或加法溢出必须按零容差处理，不能绕过未来时间检查；
- Provider 数据契约必须限制 Provider/通道/备注数量和 ID/显示文本长度，并拒绝空名称/来源/标签、重复备注、`Available` 空通道及读取完成后仍返回 `Loading`；超长字符串只能执行有界前缀检查，不能进入哈希、大小写转换、元数据比较或错误消息；
- Provider 契约审计累计到 4096 条 Issue 后必须停止后续字段扫描，并且最多返回 4096 条；即使每个允许数量内的通道同时违反多个字段，也不得继续扩大错误数组；
- Dashboard 必须按 Provider 注册索引接收结果，并在进入 UI、历史或记录前核对完整契约和注册元数据；畸形结果只能变成固定且不回显原负载的 Error Snapshot，变化 ID 不得增加 Dashboard 状态数量；
- CPU/内存/网络/磁盘/GPU/SMC 的底层计数或浮点值即使损坏到溢出边界，也只能省略或降级，不得在聚合、格式化或整数转换时崩溃；
- SMC CPU/GPU 温度 key 必须按 M1–M5 代际固定选表，各代使用无真实读数 fixture 验证；CPU 品牌字符串不得保留或导出，未知代际只能尝试固定通用键并安全降级；
- 重复 Provider ID 必须保留给契约审计报告，不得在并发读取或 Dashboard 排序阶段触发运行时崩溃；
- 离线状态不影响本地功能。

## 硬件验收

- 记录芯片架构和 macOS 版本，但不记录唯一 ID；
- 当前 Mac 上确认 AppleSPUHIDDevice、AppleSMC 和 Force Touch 驱动的存在性；
- 任何普通权限读取都需检查数值范围、变化趋势和时间戳；
- 使用 `sensorlab-selftest --spu-stability` 连续读取至少 20 次，记录实时、缓存降级和失败数量；
- 没有第二台机型时不得宣称广泛兼容。

## 开源发布门槛

- 用户确认正式项目名和许可证；
- 完整 Xcode 可复现构建；
- 第三方许可证与 NOTICE 完整；
- 隐私清单和权限用途文案完成；
- App Bundle 内存在可解析的 `PrivacyInfo.xcprivacy`，其声明与实际离线行为一致；
- App Bundle 内存在可解析的简体中文 `Localizable.strings`，Release 可执行文件不得包含开发机的绝对用户目录构建路径；
- README 有安装、构建、截图、限制和安全说明；
- README 截图来自明确标识的确定性 Demo 模式，不包含开发机真实传感器读数；
- 清理 `.work`、构建产物和机器专属信息；
- 在新 clone 中完成构建和测试；
- `scripts/release-audit.sh` 在 CI 中通过，且只审计仓库内已跟踪文件和发布资源；
- CI 必须同时编译 Debug 与优化后的 Release 产品，并使用 Release 可执行文件组装、lint、启用 Hardened Runtime 和严格验签本地 App Bundle；
- 再创建公开 GitHub 仓库和首个 pre-release。

## 当前不阻塞本地 MVP、但阻塞公开二进制发布

- Developer ID 签名与公证；
- Developer ID 身份下的 Hardened Runtime 最终复验（当前 ad-hoc Hardened Runtime 的 Demo 启动已通过）；
- App Sandbox 策略；
- 麦克风/定位权限完整验证；
- 多机型兼容性矩阵。
